# Решения, принятые при реализации этапа 1

Выписка из журнала выполнения плана: решения там, где спецификация и план молчали или расходились, и отложенные мелочи. Формат строки: решение — причина — чем это грозит, если неверно.

## Решения

- Setup: Ruling: no separate worktree — the session's designated branch claude/intelligent-lovelace-lzkbvh in a fresh repo is the isolated workspace — cost if wrong: none, no other branch exists.
- Task 1: Ruling: scaffolded in a scratch directory and copied in (create-next-app refuses non-empty dirs) — same result — cost if wrong: none.
- Task 1: Ruling: cacheComponents and partialPrefetching (create-next-app defaults) turned off — every page reads the session and live data; the Cache Components model would require Suspense plumbing with no benefit here — cost if wrong: re-enable flag and add boundaries later.
- Task 1: Ruling: @types/node raised to ^22 — vitest 5 peer requirement; runtime is Node 22 — cost if wrong: none.
- Task 1: Ruling: test helper applies generated SQL itself and strips the "public". qualifier instead of using drizzle's migrator with migrationsSchema — drizzle-kit qualifies foreign keys with "public", which breaks per-schema isolation — cost if wrong: test and production migration paths differ slightly; e2e uses the real migrator.
- Task 1: Ruling: SESSION_SECRET has a development default and is mandatory only when NODE_ENV=production — keeps local start one command — cost if wrong: a production deploy without the variable fails at first env read (intended).
- Task 3: Ruling: tables named app_user and user_session instead of user and session — "user" is a reserved word in PostgreSQL and needs quoting in every hand-written query — cost if wrong: rename migration.
- Task 3: Ruling: deactivating a user also deletes their sessions; ctxFromSessionToken rejects inactive users — a deactivated account must lose access immediately — cost if wrong: none.
- Task 3: Ruling: tsconfig target raised from ES2017 to ES2022 — BigInt literals in money rounding; runtime is Node 22 and evergreen browsers — cost if wrong: none.
- Task 5: Ruling: plain Leaflet inside a client component instead of react-leaflet (dependency removed) — fewer moving parts, no SSR workarounds — cost if wrong: none.
- Task 5: Ruling: reference pages are one config-driven route /refs/[kind] with a generic EntityForm rather than four hand-written page sets — same behaviour, a quarter of the code — cost if wrong: an entity needing a bespoke form gets its own page.
- Task 5: Ruling: added SESSION_COOKIE_SECURE (defaults to true in production) — a plain-HTTP install could not log in with a Secure cookie — cost if wrong: none; default matches the spec.
- Task 5: Ruling: zod messages switched to the Russian locale and form errors are labelled with the field's Russian label — spec requires a Russian UI — cost if wrong: none.
- Task 5: Ruling: Google-hosted fonts from the scaffold replaced by the system font stack — the build must not depend on reaching fonts.googleapis.com — cost if wrong: cosmetic.
- Task 6: Ruling: order table is named sales_order — "order" is a reserved word in PostgreSQL — cost if wrong: rename migration.
- Task 6: Ruling: upsertOrder also returns lineResults (per line: added/updated/skipped) and never deletes lines missing from the input — an import file is applied row by row and one row is one line; deleting absent lines would wipe the rest of the order when a single row is re-processed — cost if wrong: a line removed in the source system stays until cancelled by hand.
- Task 6: Ruling: amounts and quantities use bigint columns — a 32-bit integer caps money at about 21 million rubles — cost if wrong: none.
- Task 6: Ruling: line price and cost are hidden from roles without money.read — spec 4.4 keeps money fields from the warehouse — cost if wrong: none.
- Task 7: Ruling: when the template says times are in the zone of the point and the point is unknown, the row reports only the unknown point — dates cannot be converted without a zone, and a second error would be noise — cost if wrong: a bad date in the same row surfaces only after the point is fixed.
- Task 7: Ruling: parseTable also rejects empty and non-workbook files with codes empty_file and unreadable_file — users will upload them; a crash is not acceptable — cost if wrong: none.
- Task 8: Ruling: saving an import template requires settings.manage (administrator); the logistician picks an existing template — spec 4.4 gives import templates to the administrator, while the plan's Task 9 scenario had the logistician save one; the spec wins — cost if wrong: loosen one permission check.
- Task 8: Ruling: counts are numbers of file rows, not orders (3 rows of 2 orders → added 3) — a row is what the user sees and fixes; per-order counts would not add up with the error-row count — cost if wrong: relabel in UI.
- Task 8: Ruling: rows of one order that disagree on point or window get error order_header_mismatch — an order has one delivery point and window; silently taking the first would hide a data problem — cost if wrong: none.
- Task 8: Ruling: a job stuck in "processing" for 10 minutes is taken again — the worker lives inside the app process and may die mid-job; re-applying is idempotent — cost if wrong: none.
- Task 8: Ruling: spreadsheet date cells are stored in import_row.raw as {$date: ISO} and revived on read — JSON would turn them into strings that no longer match the date format — cost if wrong: none.
- Task 8: Ruling: row numbers are position-based (data row i → i+2); blank spreadsheet rows skipped by the parser shift later numbers — cost if wrong: an off-by-n row number in XLSX files with blank lines; noted for the final review list.
- Task 9: Ruling: the template (column mapping) is created by the administrator from a sample file, with columns suggested from header names; the logistician uploads against an existing template — follows the Task 8 ruling on spec 4.4 — cost if wrong: one permission check.
- Task 9: Ruling: e2e expectations are in rows (5 added, 1 error; after fixing the row 6 and 0; same file again: 5 skipped) rather than the plan's "Добавлено 4" — follows the Task 8 ruling that counts are rows — cost if wrong: none.
- Task 9: Ruling: error rows are editable only after the job has been processed — fixing a row applies it immediately, which would be surprising before the user pressed "Загрузить заказы" — cost if wrong: one prop.
- Task 9: Ruling: server action body limit raised to 20 MB — the default 1 MB would reject ordinary spreadsheets — cost if wrong: none.
- Task 9: Ruling: e2e global setup creates five demo points (WH-1, RC-1, SHOP-1..3) until Task 23's seed replaces it — the import scenario needs points to resolve — cost if wrong: none.
- Task 11: Ruling: tripFacts() (src/server/services/tripFacts.ts) returns false for plan, executor, execution events and completeness until Tasks 14, 16 and 20 extend it — those tables do not exist yet; transitions depending on them stay closed meanwhile — cost if wrong: those later tasks must remember to extend the function (listed in their briefs as "extend tripFacts").
- Task 11: Ruling: cargo and stops are editable while the trip is draft or planned; assigned and later are locked (trip_locked) — cargo changes after assignment would silently invalidate the confirmed executor; planned stays editable because spec 8.2 replanning changes stops — cost if wrong: Task 14/15 must flag a saved plan whose stops snapshot no longer matches the trip.
- Task 11: Ruling: moveTrip() is exported as a permission-free in-transaction status change next to the public transitionTrip() — Task 16's driver-link events need to move a trip without a user role — cost if wrong: none.
- Task 11: Ruling: transitionTrip permissions by target: closed → trip.close, in_progress/completed → execution.write, otherwise planning.write — matches spec 4.4 table — cost if wrong: one mapping.
- Task 11: Ruling: a stop's window is the intersection of its orders' windows (latest start, earliest end) — a truck delivering two orders at one point must satisfy both — cost if wrong: an empty intersection shows as late in ETA, which is the honest result.
- Task 11: Ruling: found while testing — unload stops used to follow the row-lock order (random uuid) instead of the order the planner added lines; fixed to follow request order — test "removes cargo and drops a stop" caught it.
- Task 11: Ruling: when applying an order's import rows fails (e.g. plan_conflict), rows are retried one by one so only the conflicting row is an error — otherwise an unchanged sibling row would be reported as failed — cost if wrong: none (found by the Task 11 import test).
- Task 12: Ruling: StopPlan carries windowEnd (plan's StopPlan did not list it) — the comparison needs it to say "к окну до 14:00" without the caller re-deriving it — cost if wrong: none.
- Task 12: Ruling: an arrival exactly at the end of the window is "risk" (lateMin 0), not "late" — the window is inclusive; late means strictly after — cost if wrong: one comparison operator.
- Task 12: Ruling: the window check uses the arrival time, not the end of service — matches the requirements example ("РЦ принимает до 14:00", arrival 13:35) — cost if wrong: stops that accept only until a time by which unloading must finish need a different rule.
- Task 12: Ruling: equal costs sort by label with Russian collation so the order is stable between renders — cost if wrong: none.
- Task 13: Ruling: parseTwoGisResponse(httpStatus, body, straightLegsM, profileComplete) — the plan listed (httpStatus, body, pointCount, straightLegsM); pointCount is redundant with straightLegsM.length + 1 and the result needs profileComplete — cost if wrong: none.
- Task 13: Ruling: 2GIS leg durations are always estimated (apportioned by straight-line length) and flagged legsEstimated — the documented response has no per-intermediate-point times; this is an open item for the live-key run already listed in the spec — cost if wrong: ETA at intermediate stops is approximate until the live check.
- Task 13: Ruling: quota counts successful 2GIS requests across the whole installation, not per organization — one key serves everyone, so a per-organization count would under-report and let the shared limit be exceeded — cost if wrong: an aggregate number is visible to every organization.
- Task 13: Ruling: Quota has an extra "live" flag so the screen can show the demo-mode label; routing_request_log records the provider and only provider "2gis" with ok=true counts — cost if wrong: none.
- Task 13: Ruling: variant token payload is HMAC-SHA256 over SESSION_SECRET, valid two hours, carrying numbers only (no geometry) — as in the plan — cost if wrong: rotating SESSION_SECRET invalidates tokens in flight (harmless).
- Task 13: Ruling: fixtures are in src/server/routing/fixtures as the plan said; hand-written from the documented shape, never recorded — spec section 3 — cost if wrong: none.
- Task 14: Ruling: plan costs live only in plan_version.cost_lines; no kind='plan' rows are written to expense, and the expense table is created in Task 20 for facts only — storing the same lines twice invites drift; economics will read the baseline plan version — cost if wrong: Task 20 reads JSON instead of rows.
- Task 14: Ruling: calculateRoutes takes an optional deps.provider and confirmFar, returns needsConfirmation — spec 6.3 says the logistician decides whether to send a request over 50 km on a demo key; the service therefore holds such a request until confirmFar is passed — cost if wrong: one extra flag.
